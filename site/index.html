Why Use This

What changes when you install it

Without it, Claude Code explores from scratch every time. With it, your codebase is indexed and every query hits exactly the files that matter.

Codebase Indexing

Smart File Selection

Hybrid index-lookup + live Glob/Grep scan. Only reads files relevant to your query. Zero API cost for scanning.

Session Tracking

Testing & Auditing

Run tests, diagnose failures, auto-fix. Audit for security, performance, dead code, and dependency health.

Token Guardrails

Web Research

Searches official docs, resolves errors, checks dependency health, finds best practices. Results cached locally.

How It Works

Three phases, zero waste

Index once, query smart, track everything.

1

Initialize

Run /ccs:init once per project. It scans every file, builds a dependency graph, ranks files by importance (S/A/B/C/D), detects patterns, and generates 4 reference docs in .ccs/ — all as local markdown.

2

Query Smart

On every query, the skill checks the pre-built index first (zero cost), then runs targeted Glob + Grep if needed, then follows dependency chains. Claude Code reads only the files that actually matter — never browses aimlessly.

3

Track Everything

Every action is logged in .ccs/task.md as a git-commit-style entry: files read, modified, created, deleted, dependencies found, test results. Context persists across the entire session without consuming API tokens.

Usage

Quick start

Install the skill, init your codebase, start building.

Terminal
# Install in your project
$ npx codebase-context-skill init

# Or with bun
$ bunx codebase-context-skill init

# Initialize the codebase index
$ /ccs:init

# Plan a feature
$ /ccs:plan "add user authentication with JWT"

# Build it
$ /ccs:build "implement JWT auth from plan"

# Run tests and auto-fix failures
$ /ccs:test --fix

# Audit before deploying
$ /ccs:audit security

# Deploy checklist
$ /ccs:deploy

Context Files

Everything lives locally

All context is stored as markdown in .ccs/. Add it to .gitignore. No cloud, no database, no dependencies.

.ccs/
  project-map.md   # File tree + dependency graph
  architecture.md   # Tech stack, patterns, data flow
  file-index.md    # Files ranked S/A/B/C/D by importance
  conventions.md   # Coding style, naming, test patterns
  task.md         # Session log (commit-style entries)
  preferences.json # Refresh mode, user settings
