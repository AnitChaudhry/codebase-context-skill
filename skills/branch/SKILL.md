# Branch with Context

## Overview
Creates or switches branches while maintaining context reference files in `.ccs/branches/`. When creating a branch, a reference file is generated that tracks the parent branch, purpose, and initial state. When switching, the reference file is read first so Claude immediately knows what this branch is about without re-scanning the codebase.

## When to Use
- Starting work on a new feature or fix
- Switching between branches mid-session
- Checking what a branch contains before merging
- Cleaning up stale branches

## Instructions

### Step 1: Detect Intent
Parse the user's input:
- **Create:** `/ccs-branch create feature-auth "Add user authentication"`
- **Switch:** `/ccs-branch feature-auth` or `/ccs-branch switch feature-auth`
- **List:** `/ccs-branch list` — show all branches with ref status
- **Clean:** `/ccs-branch clean` — remove stale refs for deleted branches
- If ambiguous, use AskUserQuestion to clarify

### Step 2: Load Context
1. Read `.ccs/file-index.md` — for dependency impact analysis
2. Check `.ccs/branches/` — list existing branch refs via Glob
3. Run `git branch -a` — get current branch state

### Step 3: Execute

#### Creating a Branch
1. Run `git checkout -b <branch-name>` via Bash
2. Detect parent branch: `git rev-parse --abbrev-ref HEAD` (before checkout)
3. Record merge-base: `git merge-base HEAD <parent>`
4. Create `.ccs/branches/` directory if it doesn't exist
5. Generate `.ccs/branches/<branch-name>.md`:

```markdown
# Branch: <branch-name>

> Generated by codebase-context-skill | <timestamp>
> Parent: <parent-branch>
> Created: <date>
> Status: active

## Purpose
<user-provided purpose or "No description — update with /ccs-branch">

## Files Changed
| File | Action | Summary |
|------|--------|---------|
(none yet)

## Diff Summary
No changes yet — branch just created.

## Dependencies Affected
(none yet)

## Commits
| Hash | Message | Files | Date |
|------|---------|-------|------|
(none yet)

## Related
- **Task:** (link to task.md entry if applicable)
- **PR:** (none yet)
- **Upstream changes since branch:** 0 commits
```

#### Switching to a Branch
1. Check if `.ccs/branches/<branch-name>.md` exists
2. If it exists, read it — display summary to user
3. If it doesn't exist, generate it from git state:
   - `git log --oneline main..<branch-name>` for commits
   - `git diff --stat main...<branch-name>` for changed files
   - `git diff --shortstat main...<branch-name>` for summary
4. Run `git checkout <branch-name>` via Bash
5. Check for staleness: compare ref timestamp with latest commit

#### Listing Branches
1. Run `git branch -a --format="%(refname:short) %(upstream:short) %(committerdate:relative)"`
2. For each branch, check if `.ccs/branches/<name>.md` exists
3. Display table: branch name, has ref (yes/no), last commit, status

#### Cleaning Stale Refs
1. Run `git branch` to get active branches
2. Glob `.ccs/branches/*.md` for existing refs
3. Delete refs where the branch no longer exists
4. Report what was cleaned

### Step 4: Track in task.md
Append to `.ccs/task.md`:

```markdown
## Task #{number}: Branch — {action} {branch-name}

**Timestamp:** {now}
**Status:** done
**Type:** branch

### Details
- **Action:** {create|switch|list|clean}
- **Branch:** {branch-name}
- **Parent:** {parent-branch}
- **Purpose:** {purpose}

### Branch Ref
- **File:** `.ccs/branches/{branch-name}.md`
- **Status:** {created|updated|read}
```

## Token Efficiency Rules
- Read the branch ref FIRST before exploring any source files
- Never re-scan the codebase to understand a branch — the ref has everything
- When switching branches, the ref tells Claude exactly what changed and why
- Keep branch refs under 100 lines — compress diffs to summaries

## Limitations
- Does not push branches to remote (use `git push` manually or `/ccs-sync`)
- Does not create pull requests (use `/ccs-pr`)
- Branch refs track git state, not unsaved editor changes
